# Лабораторна робота № 1

Тема: базові операції у Java — змінні, методи та класи.

Це початкова заготовка Maven-проєкту. Вона містить конфігурацію
складання, Maven Wrapper, каркас точки входу та публічні тести для всіх
12 варіантів. Готового предметного класу індивідуального варіанта у
заготовці немає.

## Потрібне середовище

- JDK 25 LTS; навчальний код компілюється для Java 21;
- Apache NetBeans 31;
- Git 2.x;
- доступ до Інтернету під час першого запуску Maven Wrapper.

Перевірка середовища у Windows:

```powershell
java --version
git --version
.\mvnw.cmd --version
```

У Linux або macOS третя команда має вигляд `./mvnw --version`.

## Порядок роботи

1. Відкрийте цю папку в Apache NetBeans як наявний Maven-проєкт.
2. У `submission.properties` замініть `NN` на номер свого варіанта від
   1 до 12. Не додавайте до файла персональних даних.
3. У пакеті `ua.khnu.kpp.lab1` створіть публічний предметний клас із
   назвою, конструктором і методами, визначеними вашим варіантом.
4. Замініть каркас у `src/main/java/ua/khnu/kpp/lab1/Main.java`
   реалізацією консольного протоколу з методичних вказівок.
5. Не редагуйте `Lab1PublicTest.java`. Додайте власний тестовий клас із
   контрольним, альтернативним допустимим і негативним сценаріями.
6. Запустіть перевірку:

```powershell
.\mvnw.cmd -B -ntp clean verify
```

Для Linux або macOS:

```bash
./mvnw -B -ntp clean verify
```

До реалізації варіанта публічні тести повинні завершуватися невдало й
повідомляти, якого класу або контракту бракує. Після завершення роботи
очікується `BUILD SUCCESS` і нульова кількість невдалих, помилкових та
пропущених тестів.

## Призначення файлів

- `pom.xml` — версії Java, JUnit і плагінів складання;
- `mvnw`, `mvnw.cmd`, `.mvn/wrapper/` — відтворюваний запуск Maven;
- `submission.properties` — номер лабораторної роботи й варіанта;
- `src/main/java` — код студента;
- `src/test/java` — публічні тести та власні тести студента;
- `docs/report.pdf` — завершений звіт;
- `.gitignore` — файли, які не потрібно публікувати.

Після успішної перевірки створіть щонайменше три змістовні коміти,
завантажте проєкт у публічний віддалений Git-репозиторій і позначте
оцінюваний коміт тегом `lab-01`. До репозиторію не додають `target/`,
паролі, токени, приватні ключі або інші секретні дані.
